## Notes

- Auto-memory migration `~/.claude/projects/-home-netrom-nimbus` → `-home-netrom-kintoun` completed at session start. Old paths still on disk but stale; cleanup pending.
- Discovered `#[expect(lint, reason = "...")]` (Rust 1.81+) — the modern alternative to `#[allow(lint)]`. Self-cleans: when the lint stops firing, `#[expect]` itself warns, forcing removal. Used on `InMemoryStorage.data` to silence the temporary dead_code warning at point A.
- Compiler errors on missing braces/semicolons point to *the next syntactically wrong thing*, not the actual missing brace. Heuristic: when error site looks correct, walk *up* the file looking for structural issues.
- Rust expression-orientation: `;` is a value-discarder (turns expression → statement that produces `()`). The last expression in a block, *without `;`*, is the block's value. Function bodies follow this rule — implicit return = trailing expression.
- `Ok(())` is the canonical "succeeded with nothing meaningful to return" payload. The `()` is both a type (unit type) and a value (the unit value). `Ok()` (with no argument) is a compile error.
- `to_ascii_lowercase()` over `to_lowercase()` for ASCII verbs — communicates intent, slightly faster (byte-level transform), length-preserving (avoids Unicode surprises like `İ` lowercasing to two characters).
- `match parts.next() { None => Ok(()), Some(_) => Err(...) }` is the more idiomatic Rust shape than `if parts.next().is_some() { ... } else { ... }`. Match on `Option` whenever you reach for `.is_some()` / `.is_none()`.

Demonstrated with hypothetical: *"would you push back if I skipped WAL?"* — yes, because M4-M8 structurally require the log; the push-back reasoning engages roadmap dependency, not industry-standard appeals.
