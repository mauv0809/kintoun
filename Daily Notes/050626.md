### 2. `serve()` refactor — JoinSet drain
- New signature: `serve(listener, storage, shutdown: F: Future<Output = ()>)`.
- `tokio::pin!(shutdown)` + `tokio::select!` between `listener.accept()` and `&mut shutdown`.
- Per-conn tasks now spawn into `JoinSet<Result<()>>` instead of bare `tokio::spawn`.
- On shutdown: break loop, `drop(listener)` (port released immediately), then `while tasks.join_next().await.is_some()` drains until clients close. No drain timeout — documented in the doc comment and ADR 0013 status note.
- Borrow-checker note (caught during impl): the user originally tried to `drop(listener)` inside the shutdown arm before `break`; the compiler doesn't reason consistently across `break` so listener appeared moved-then-used. Hoisting `drop(listener)` after the loop is functionally equivalent and keeps the borrow checker happy.

### 3. `main.rs` full rewrite
- `enum Mode { Repl, Server(SocketAddr) }` (tuple variant, single-field-where-name-implies-role per saved enum-shape rubric).
- Hand-rolled `parse_args(Vec<String>) -> Result<Mode>` with `.skip(1)` iterator pattern + 6 unit tests covering the full grammar (REPL on no args; Server on `--bind <addr>`; explicit errors on bare `--bind`, invalid addr, extra args, unknown flag).
- `fn main` stays sync. `run_server(addr)` builds a multi-thread tokio runtime lazily — REPL path stays runtime-free, matching ADR 0013's principle "async earns its keep where concurrency exists."
- `tokio::signal::ctrl_c()` wrapped in `async { let _ = ...await; }` to satisfy `serve`'s `Future<Output = ()>` bound (ctrl_c returns `Result<(), io::Error>`).

### Decisions made (afternoon)
- **`--bind <addr>` always requires a value.** Bare `--bind` is "missing argument" error. Default 127.0.0.1:4242 lives in error text as a documented recommendation but never auto-applies. Most explicit; bare-flag-with-default is unconventional.
- **Lazy runtime on server branch.** REPL stays sync. Three extra lines for the explicit `Builder::new_multi_thread().enable_all().build()` + `block_on` shape.
- **JoinSet-tracked drain.** Stricter than ADR 0013's "let in-flight finish naturally" prose — `serve()` actually awaits drain rather than relying on runtime shutdown to cancel tasks.
- **`F: Send` is NOT needed on `serve()`.** Doc was wrong; the pinned shutdown future stays on the serve task's stack and is never moved across threads. `S: Send + 'static` IS needed because spawned `handle_connection` tasks capture `Arc<Mutex<S>>` and may run on any worker thread.
