## Decisions
- StoredValue tagged enum (Str/Int) over String-only storage — preserves type-system honesty + future-proofs M4+ variants. ADR 0008.

- anyhow at REPL boundary, thiserror at library layers — codified as a project convention for M2+ async code. ADR 0010.
- cargo-llvm-cov over cargo-tarpaulin (LLVM-based, accurate branch coverage, modern Rust default). No threshold yet — measure first, ratchet at M3. ADR 0011.

**Notable corrections / learnings (5 nominations filed):**
- Rust 2018+ module convention (`src/foo.rs` + `src/foo/`) over older `src/foo/mod.rs`. User instinct was correct; my older guidance wasn't. Hit the "ambiguous module" Cargo error when both ended up created.
- `usize::to_be_bytes()` is platform-dependent length (4 bytes on 32-bit, 8 on 64-bit). Caused a green-but-wrong oversize_decode test (8 bytes written, decoder read first 4 as `0x00000000`, returned empty frame, test name lied). Caught in code review.
- Green-but-wrong test pattern: passing tests can be testing the wrong thing if input gets reinterpreted (wrong width, wrong endianness, mixed unrelated probes in one body). Read tests against their invariant, not just their assertion.
- Process: surface alternatives for foundational deps before scaffolding. User caught me adding tokio without an alternatives discussion; the resulting comparison (vs. async-std, smol, glommio, sync threads) sharpened the rationale even though tokio remained the choice.
- Tuple struct `.0` access vs named field for non-trivial wrappers — refactored `Frame(Vec<u8>)` → `Frame { payload: Vec<u8> }` before tests landed. Future-proofs M4's `frame_type` byte addition.
