## Hard Rules
- [050226] Avoid making decisions where a refactor is already certain. When weighing options, classify the eventual refactor as *certain* (forced by the milestone arc) or *possible* (depends on later choices). For certain refactors, pick the option that absorbs the cost upfront — short-term simplicity is not worth eventual churn. The "you'll learn from a future refactor" argument applies only to *possible* refactors. [Source: user override 050226]
- [050226] ADR rigor scales with stakes. Low-stakes decisions get a thin recording (Context + Decision). High-stakes decisions (those that constrain the milestone arc) get a thicker Alternatives section. Forcing equal rigor on every ADR inflates the low-stakes ones and dilutes the high-stakes ones. [Source: user override 050226]
- [050426] Surface alternatives for foundational dependencies before scaffolding code that uses them. Even when the answer is "obvious," the discussion sharpens the rationale and creates an audit trail for future revisits. [Source: user override 050426]

## Platform & Tool Rules
- [043026] When running Rust/Cargo commands via the Bash tool, prepend `~/.cargo/bin` to PATH or use full paths — the Bash tool does not source `~/.cargo/env`. [Source: empirical 043026]

## Project Patterns
- [043026] Default values belong in the parser, not the type. When a command has an optional argument with a default (e.g. `incr foo` defaults to `by: 1`), fill the default in `from_str` so the enum variant is always uniform. Downstream code never branches on "did the user supply this?" [Source: agent inference 043026]
- [043026] Per-arm TDD discipline for `match` dispatchers: only implement an arm when a red test demands it. Leave undemanded arms as a panic stub. The compiler still enforces exhaustiveness; panics on unimplemented arms are loud and informative during development. [Source: agent inference 043026]

## Rust Idioms
- [050226] `#[expect(lint, reason = "...")]` is the modern alternative to `#[allow(lint)]` (stable since Rust 1.81). It silences the lint AND requires the lint to be firing — when the lint stops firing, the `expect` itself warns ("expectation unfulfilled"), forcing removal. Use for *temporary* suppressions (work-in-progress fields, deferred impls) where the suppression should expire. [Source: agent inference 050226]
- [050226] Use `to_ascii_lowercase()` over `to_lowercase()` for ASCII-only matching (command verbs, fixed identifiers). `to_lowercase()` runs full Unicode case-folding (locale-independent but costly; can expand code points). `to_ascii_lowercase()` is a byte-level transform: faster, length-preserving, and honest about intent. Both allocate a new `String`. [Source: empirical 050226]
- [050226] Compiler errors on structural issues (missing brace, `;`, unclosed paren) often point to *the next syntactically wrong thing*, not the actual missing element. Walk *up* the file looking for structural mismatch when the error site looks correct. Heuristic: trust syntax that mirrors working code in the same file; if `Ok(())` looks right by symmetry, the bug is elsewhere. [Source: empirical 050226]
- [050226] Rust is expression-oriented: `;` discards a value, it does not terminate a statement. The last expression in a block *without* trailing `;` is the block's return value. Adding `;` to the final `match` in a function body turns it into a `()` statement, producing "expected T, found ()". Diagnostic heuristic: that error message → walk to the bottom of the function, look for an offending `;`. [Source: empirical 050226]
- [050426] Rust 2018+ module convention: `src/foo.rs` + `src/foo/{submodule}.rs`, not `src/foo/mod.rs`. Both compile identically; the flat-file form is the modern convention — `mod.rs` is the 2015-edition legacy style. Cargo errors only when *both* exist for the same module ("file for module `foo` found at both"). Default to the 2018+ form in all new code. [Source: empirical 050426]
- [050426] Tuple struct for true newtypes where the variant name implies the role (`Frame(Vec<u8>)`). Named struct when fields are semantically distinct or the type may grow fields (`Frame { payload: Vec<u8> }`). Prefer named-field form when `item.0.len()` would require looking up the definition; `item.payload.len()` is self-documenting and future-proofs additive changes. [Source: user feedback 050426]
- [050126] `?` propagates from the immediately enclosing function only — it cannot escape a closure. Using `?` inside `and_then(|s| ...)` attempts to early-return from the closure, not the outer function. Fix: lift the fallible step out of the closure and use `match` or a let-binding in the function body. [Source: empirical 050126]
- [050126] Pin the target type at the `parse()` site with turbofish (`s.parse::<u64>()`) when inference stalls at a closure boundary. "Type annotations needed" inside a closure usually means the generic type can't be resolved from downstream context; annotating the `parse()` call resolves it. [Source: empirical 050126]
- [050126] `From<E1> for E2` cannot capture calling-scope context — the impl only sees the source error. When an error variant needs to carry context available at the call site (e.g. the bad input the user typed), use `.map_err(|e| Variant { input: s.to_string(), reason: e.to_string() })?` instead of relying on auto-`?`-via-`From`. [Source: agent inference 050126]
- [050126] Asymmetric error variants for asymmetric data sources is idiomatic Rust: `&'static str` for hardcoded labels you control (zero alloc), `String` for user/runtime input, struct variant when multiple pieces of context are needed. Mixing these shapes in one enum is intentional, not inconsistent. [Source: agent inference 050126]
- [050126] Patterns are a separate language from expressions — no function calls, no method calls, no construction inside a pattern. To assert against a complex match arm value: bind the inner data and assert separately (`Err(ParseError::UnknownCommand(s)) => assert_eq!(s, "foo")`). Bind-then-assert produces a diff on failure; a guard (`if`) produces only a generic "didn't match" panic. [Source: empirical 050126]

## Known Failure Modes
- [050426] `usize::to_be_bytes()` / `usize::to_le_bytes()` returns `[u8; 4]` on 32-bit and `[u8; 8]` on 64-bit. When serializing to a wire format with a fixed-width length prefix, always cast before calling: `(value as u32).to_be_bytes()` or `u32::try_from(value)?.to_be_bytes()`. Never pass `usize` directly to `to_be_bytes()` on a wire format. [Source: empirical 050426]
- [050426] Green-but-wrong tests: when test input involves type coercion or byte-level construction, mentally trace the actual bytes that result. A test can pass its assertion on *reinterpreted* data while the declared invariant is untested. Defenses: (1) read every test against its declared invariant, not the assertion alone; (2) each test body exercises one behavior variant; (3) do not combine encode and decode probes in one body. [Source: empirical 050426]
- [043026] Rust orphan-file silent failure: a `.rs` file in `src/` not declared via `mod foo;` in `lib.rs` or `main.rs` is silently ignored. `cargo test` reports "0 tests" with no error. Always read the `Running unittests <path>` line in cargo output to confirm the correct crate root. [Source: empirical 043026]
- [050426] `cargo clippy` does not subsume `cargo fmt` — a file can pass clippy and fail `fmt --check` simultaneously. Clippy is a lint check; rustfmt is a layout check. bacon's default jobs do not run fmt. Three-layer prevention: (1) IDE format-on-save, (2) bacon `fmt` job, (3) `.githooks/pre-commit`. CI remains the final catch. [Source: empirical 050426]
- [050426] Line coverage % is dragged down by defensive `panic!` arms in test bodies. These arms only execute when a test fails, so coverage tools count them as 0% covered. Production code coverage is what matters; report the number with that caveat. Do not refactor tests to chase the metric. [Source: empirical 050426]

## Testing Patterns
- [050626] `std::future::pending::<()>()` as a "never resolves" shutdown placeholder for tests. When a function takes `shutdown: F: Future<Output = ()>`, pass `pending::<()>()` in tests that want "serve forever" behavior. The turbofish `::<()>` pins the output type so `F: Future<Output = ()>` is satisfied (without it, inference fails). Production callers pass real signals; one signature serves both. [Source: empirical 050626]
- [050426] Generic-trait contract test pattern: `pub(crate) mod contract` with test functions generic over the trait (`pub fn foo<S: Trait>(s: &mut S)`), plus a per-impl `macro_rules! delegate!` that generates thin `#[test]` wrappers. New implementations inherit all contract tests by adding one wrapper module — no test rewrites needed. Idiomatic in Rust where each test must be a concrete `#[test] fn`. [Source: agent inference 050426]
- [050626] Async server-test pattern: `tokio::spawn` the server task, then drive the client side from the test body. Awaiting the server function inline on the test task prevents the client side from running and deadlocks. Bind the JoinHandle as `_server` if shutdown assertion is not needed, or keep it to assert `Ok` at the end of the test. [Source: empirical 050626]
- [050626] Two-layer JoinHandle peel: when a spawned `async fn() -> Result<T, E>` is awaited, the result is `Result<Result<T, E>, JoinError>`. `is_ok()` only checks the outer layer — a function returning `Err(...)` produces `Ok(Err(...))` and silently passes. Idiom: `let inner = handle.await.expect("task panicked"); assert!(inner.is_ok(), "{inner:?}");` — separate message per layer. [Source: empirical 050626]

## Async / Tokio Patterns
- [050626] `tokio::task::JoinSet` + `join_next().await` until empty is the canonical graceful-drain idiom. On shutdown: drop the listener (releases the port immediately), then `while tasks.join_next().await.is_some() {}` until drained. Per-task results are inspectable by binding the `Some(_)` value. Bare `tokio::spawn` with discarded JoinHandle gets aborted on runtime shutdown — the connection's in-flight response is severed. [Source: empirical 050626]
- [050626] `tokio::pin!(shutdown)` + `tokio::select!` + `&mut shutdown` for cancellable async loops. When a function takes `F: Future<Output = ()>` as a cancel signal, `F` is not `Unpin` in general. `tokio::pin!(shutdown);` pins it on the stack; `select!` arms poll `&mut shutdown` repeatedly without consuming it. Without the pin the borrow checker rejects the repeated poll. [Source: empirical 050626]
- [050626] Lazy tokio runtime: `Builder::new_multi_thread().enable_all().build()` + `runtime.block_on(...)` when only one dispatch branch needs async. Keep `fn main()` sync; parse args first; build the runtime only on the async branch. The REPL path stays runtime-free; the server path gets the multi-thread runtime. `enable_all()` is mandatory — `tokio::signal::ctrl_c()` requires both the I/O driver and the time driver; without it the future hangs forever. [Source: empirical 050626]
- [050626] Borrow-checker quirk in `select!`/`break` patterns: `drop(x)` inside a `break` arm can produce a false "use of moved value" on subsequent iterations because the compiler does not always reason that `break` precludes further iterations. Hoist `drop(x)` to immediately after the loop — functionally identical (loop has exited) and satisfies the borrow checker. General heuristic: when a borrow-checker error appears inside a `select!`/`break`, try moving the drop to the post-loop position before adding lifetime annotations. [Source: empirical 050626]
- [050626] `F: Send` is required only when a future crosses thread boundaries via `tokio::spawn` or `JoinSet::spawn`. A future polled in-place via `tokio::pin!` + `select!` stays on the calling task's stack for the duration. `runtime.block_on(f)` runs `f` on the calling thread — `f` need not be `Send`. Over-bounding with `F: Send` on every generic future parameter is a common mistake; add it only when `F` is explicitly spawned to another task. [Source: empirical 050626]
- [050626] `std::sync::MutexGuard` is `!Send` — the compiler enforces "no lock across `.await`" automatically on multi-thread Tokio runtimes. Acquire the lock in a block scope so the guard drops before any `.await`. Use `tokio::sync::Mutex` only when you genuinely must hold the lock across an await (rare; carries async-machinery overhead). [Source: empirical 050626]
- [050626] Pull sync helpers out of async functions to make the await/lock boundary visible at a glance. When a sub-pipeline (parse → lock → execute → format) has no awaits, extract it to a sync fn. Reviewers immediately see what holds locks vs. what suspends without reading the full loop body. [Source: agent inference 050626]

## Code Review Heuristics
- [050626] `std::prelude::v1::Result` in a type annotation is an IDE "Insert explicit type" auto-fill artifact — no human writes the fully-qualified prelude path. On `tokio::spawn` calls, inference fills the JoinHandle type entirely without annotation. Spotting this path is a one-line cleanup signal. [Source: empirical 050626]
